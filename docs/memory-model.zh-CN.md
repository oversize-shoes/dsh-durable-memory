# 这个插件的记忆怎样工作

## 是跨会话记忆吗？

是。保存成功后，条目存放在 DSH 的独立持久化存储中，而不是只存在当前聊天上下文里。同一工作目录下的新会话、DSH 重启后的会话，都可以读取项目记忆。全局记忆可以跨工作目录使用；不同 DSH_HOME、不同设备默认不共享。

项目范围按真实工作目录区分，不按会话标题或 Git 仓库名称区分。子目录和 worktree 默认隔离。旧版条目可能只记录范围哈希；新版保存时还记录项目路径，便于面板识别。

记忆不会修改或训练模型权重。召回只是把相关历史条目作为上下文提供给当前模型，因此可能影响回答，也会消耗上下文 Token。旧事实可能过时，应由当前用户请求和实际环境校正。

## 什么时候写入？

当前有两个写入入口：

1. 用户在“记忆”面板中新增或编辑，点击保存后直接写入，不调用模型。
2. 模型调用 durable_memory 的 save/update/delete 操作。你可以明确说“记住这个项目使用 pnpm”；插件也提示模型在工作中保存稳定约定和经验，因此模型可能自行选择调用工具。调用是否发生取决于模型，不能保证每轮都提炼。

仅发送一条消息、打开新会话、结束一轮任务，不会由插件自动创建记忆。自动召回只读取数据，不新增、不修改记忆。当前没有回合结束后的后台总结/提炼任务。

因此判断“是否已经记住”，以面板里出现条目或保存工具返回成功为准，不能只相信模型在普通文本里说“我记住了”。

## 什么时候读取？

在模型请求准备阶段，插件根据新收到的消息进行关键词匹配，在配置的条数与字符预算内提供相关记忆。第一次还没有查询时，会提供预算内最近/固定的条目。模型也可以主动调用 search 查询。

面板是管理视图，能查看所有保存条目；某条记忆出现在面板中，不代表每次请求都会把它发送给模型。只有被检索选中的条目才自动注入。

当前中文采用词片段、英文采用关键词匹配，没有向量语义检索，所以换一种说法可能匹配不到。遇到不确定情况，可以明确要求模型调用 durable_memory 查询关键词。

## 删除之后会怎样？

删除后，该条目不再用于后续召回。过期条目同样不召回，但保留在面板中供检查/清理。历史对话日志、模型已经看到的上下文和外部备份不会被倒回或抹除。

## GitHub 安装和安装包

两种方式最终都安装同一份插件。GitHub 仓库安装会从指定 Git 提交/标签取得代码；tgz 是预先打包的发布快照，便于下载、校验和离线安装。

本插件的 Host 和浏览器 JS 都已提交到仓库，没有 prepare/install 编译脚本，所以不必须使用 tgz。推荐固定版本标签，以免主分支更新改变已验证行为。
